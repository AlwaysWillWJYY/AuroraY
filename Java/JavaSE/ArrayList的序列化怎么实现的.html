    ArrayList的序列化怎么实现的

    AuraroJ 2024/11/28

    # 一、序列化方法调用规则

    在 Java 的序列化过程中，遵循以下规则：

    • 自定义方法优先：如果被序列化的类中定义了 writeObject 和 readObject 方法，虚拟机会试图调用对象类里的这两个方法，以此进行用户自定义的序列化和反序列化操作。通过自定义这两个方法，用户能够按照自己的需求来控制序列化的具体过程，例如在序列化过程中可以动态改变要序列化的数值等。
    • 默认方法兜底：若类中没有定义 writeObject 和 readObject 方法，则默认调用 ObjectOutputStream 的 defaultWriteObject 方法以及 ObjectInputStream 的 defaultReadObject 方法来完成序列化和反序列化操作。

    # 二、ArrayList 序列化相关情况

    # （一）底层存储及 transient 关键字使用

    ArrayList 底层是通过 Object 数组来完成数据存储的，不过这个用于存储数据的数组被声明成了 transient。

    原因解析： ArrayList 实际上是动态数组，具有自动扩容的特性。例如每次在放满以后会按照设定的长度值自动增长，如果将数组自动增长长度设为 100，但实际只存放了一个元素，按照常规序列化方式，就会序列化 99 个 null 元素。为了避免在序列化的时候将这么多无用的 null 元素同时进行序列化，浪费空间以及可能带来的其他不必要的影响，ArrayList 把元素数组设置为 transient，使其在默认的序列化策略中不会序列化该数组字段。

    # （二）重写 writeObject 和 readObject 方法

    ArrayList 重写了 writeObject 和 readObject 方法，具体代码及解析如下：

    # 1. readObject 方法

    private void readObject(java.io.ObjectInputStream s)
    throws java.io.IOException, ClassNotFoundException {
    elementData = EMPTY_ELEMENTDATA;
    // 先读取size以及其他隐藏的相关信息，这里调用了默认的反序列化方法读取基础信息
    s.defaultReadObject(); 
    // 读取容量信息，不过此处在代码逻辑中被忽略（readInt(); // ignored）
    s.readInt(); 
    if (size > 0) {
        // 类似克隆操作，根据实际元素个数（size）而不是容量（capacity）来分配数组空间
        ensureCapacityInternal(size); 
        Object[] a = elementData;
        // 按照正确的顺序读取所有元素，逐个从输入流中读取对象并放入已分配好的数组中
        for (int i = 0; i < size; i++) {
            a[i] = s.readObject();
        }
    }
}

    这个 readObject 方法的主要作用是从输入流中反序列化出 ArrayList 对象。首先初始化底层数组为一个空数组（EMPTY_ELEMENTDATA），接着利用默认的反序列化读取基础信息，然后根据实际要读取的元素个数来合理分配数组空间，最后按顺序从输入流中读取每个元素填充到数组中，完成反序列化重建 ArrayList 对象的操作。

    # 2. writeObject 方法

    private void writeObject(java.io.ObjectOutputStream s)
    throws java.io.IOException{
    // 先写出元素个数以及其他隐藏的相关信息，同样先调用默认的序列化方法来处理基础部分
    int expectedModCount = modCount;
    s.defaultWriteObject(); 
    // 写出元素个数作为容量，目的是为了与克隆操作在行为上保持兼容性
    s.writeInt(size); 
    // 按照正确的顺序写出所有元素，逐个将数组中的元素写入输出流
    for (int i = 0; i < size; i++) {
        s.writeObject(elementData[i]);
    }
    if (modCount!= expectedModCount) {
        throw new ConcurrentModificationException();
    }
}

    writeObject 方法则是负责将 ArrayList 对象序列化到输出流中。先是记录当前的修改次数（modCount），调用默认序列化方法处理基础信息，接着写出元素个数，再依次将数组中的元素逐个写入输出流。最后通过检查修改次数是否发生变化来确保在序列化过程中没有出现并发修改异常，如果出现不一致（modCount 改变了），则抛出 ConcurrentModificationException 异常，以此保证序列化操作的一致性和数据的完整性。

    通过重写这两个方法，ArrayList 实现了对自身的合理序列化与反序列化，避开了因底层数组的 transient 声明而导致的默认序列化问题，同时也保证了数据的准确处理以及在多线程等复杂环境下的序列化正确性。

    总之，了解 ArrayList 在序列化方面的这些机制和实现细节，有助于更深入地理解其内部工作原理以及 Java 序列化机制在具体集合类中的应用情况。
